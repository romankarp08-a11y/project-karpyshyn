# ЧАСТИНА І. ТЕХНІЧНЕ ЗАВДАННЯ (ТЗ)

## 1. Загальні відомості
* **Повна назва системи:** Вебзастосунок електронної комерції «Інтернет-магазин одягу «TrendWave»»[cite: 6].
* **Умовне позначення:** ІС «TrendWave».
* **Замовник:** Кафедра програмної інженерії / керівник навчального проєкту[cite: 6].
* **Виконавець:** Студент групи КН-4 Карпишин Роман Олексійович[cite: 6].
* **Підстава для розроблення:** Індивідуальне навчальне завдання з дисципліни проєктування програмного забезпечення[cite: 6].
* **Строки виконання робіт:** Початок — 02.11.2026 р., планове завершення — 20.12.2026 р. (7 навчальних тижнів)[cite: 6].

## 2. Призначення і цілі
* **Призначення системи:** Автоматизація процесів онлайн-продажу одягу, інтерактивного підбору розміру за індивідуальними антропометричними параметрами покупця, обліку складських залишків за розмірною сіткою та обробки замовлень[cite: 6].
* **Цілі створення системи:**
  1. Зменшити кількість повернень товарів через невідповідність розміру шляхом впровадження автоматизованого калькулятора підбору посадки одягу[cite: 6].
  2. Скоротити час оформлення замовлення покупцем до ≤ 3 хвилин (не більше 4 кроків) за рахунок мінімалістичного та адаптивного інтерфейсу[cite: 6].
  3. Забезпечити оперативний облік залишків за комбінацією «колір + розмір» і прозоре відстеження статусів замовлень для менеджера та клієнта[cite: 6].
* **Цільова аудиторія (ролі користувачів):**
  * *Покупець (гість та зареєстрований користувач)* — перегляд каталогу, підбір розміру, оформлення замовлень, відстеження статусів, додавання відгуків[cite: 6].
  * *Менеджер (контент-менеджер / менеджер замовлень)* — наповнення каталогу, контроль залишків по розмірах, обробка замовлень і додавання ТТН[cite: 6].
  * *Адміністратор* — керування обліковими записами, призначення ролей і контроль стабільності системи[cite: 6].

## 3. Опис предметної області
Предметною областю є роздрібна електронна торгівля одягом (B2C e-commerce)[cite: 6].
* **Основні сутності:** Користувач (Покупець, Менеджер, Адміністратор), Товар (модель одягу), Варіація товару (конкретний колір, розмір, артикул SKU, залишок на складі), Таблиця лекал (еталонні заміри для кожного розміру з урахуванням крою), Кошик, Замовлення, Відгук[cite: 6].
* **Ключові бізнес-процеси:**
  1. *Наповнення каталогу:* менеджер створює картку товару, вказує тип крою (*oversize, regular, slim fit*), завантажує таблицю замірів та вносить кількість одиниць для кожного розміру[cite: 6].
  2. *Підбір та купівля:* покупець фільтрує каталог, вводить свої заміри (зріст, груди, талія, стегна), отримує рекомендований розмір, додає товар у кошик та оформлює замовлення[cite: 6].
  3. *Виконання замовлення:* система автоматично резервує (списує) обраний розмір зі складу; менеджер підтверджує замовлення, передає його службі доставки та фіксує номер ТТН[cite: 6].
* **Обмеження предметної області:**
  * Оплата здійснюється через інтеграцію з платіжним шлюзом (у навчальному прототипі — імітація онлайн-оплати та післяплата)[cite: 6].
  * Доставка підтримується в межах України через служби «Нова Пошта» та «Укрпошта»[cite: 6].
  * Користувач не може замовити більше одиниць товару, ніж є в наявності для обраного кольору та розміру[cite: 6].

## 4. Вимоги до системи
* **Функціональні вимоги:** Реалізація 15 функціональних модулів (`FR-01` — `FR-15`), зокрема: автентифікація та розмежування ролей (`FR-01`, `FR-15`), каталог із багатокритеріальною фільтрацією (`FR-02`, `FR-03`), збереження параметрів фігури та інтелектуальний підбір розміру (`FR-05`, `FR-06`), кошик і оформлення замовлення (`FR-08`, `FR-09`), трекінг статусів і відгуки (`FR-10`, `FR-11`), адміністративне керування товарами, залишками й замовленнями (`FR-12` — `FR-14`)[cite: 6]. *(Детальний перелік наведено у Частині ІІ — SRS).*
* **Нефункціональні вимоги (`NFR-01` — `NFR-08`):**
  * *Продуктивність:* завантаження сторінок ≤ 1,5 с при 4G/Wi-Fi; підтримка до 200 одночасних користувачів із часом відповіді API ≤ 500 мс (95-й перцентиль)[cite: 6].
  * *Безпека:* хешування паролів алгоритмом `bcrypt` (cost ≥ 10) або `Argon2id`; шифрування трафіку за протоколом `HTTPS (TLS 1.2/1.3)`; рольовий контроль доступу (RBAC)[cite: 6].
  * *Надійність:* доступність сервісу (Uptime) ≥ 99,5% на місяць; автоматичне резервне копіювання БД кожні 24 години[cite: 6].
  * *Зручність та сумісність:* оформлення покупки ≤ 4 кроки / 3 хв; адаптивна верстка для екранів 360–1920 px у браузерах Chrome, Firefox, Safari, Edge[cite: 6].
* **Вимоги до інтерфейсів, даних, технологій та середовища:**
  * *Інтерфейси:* вебінтерфейс клієнтської та адміністративної частин, RESTful JSON API для взаємодії клієнта й сервера[cite: 6].
  * *Дані:* реляційна СКБД (PostgreSQL або MySQL) із забезпеченням цілісності зовнішніх ключів та транзакційності при списанні складських залишків[cite: 6].
  * *Технологічний стек:* Frontend — HTML5, CSS3, JavaScript (React або Vue.js); Backend — Python (FastAPI / Django) або PHP (Yii2 / Laravel); контроль версій — Git / GitHub[cite: 6].
  * *Середовище розгортання:* хмарний хостинг / VPS із підтримкою контейнеризації (Docker) та вебсервером Nginx[cite: 6].

## 7. Порядок контролю та приймання
* **Види контролю та тестування:**
  * Модульне тестування (Unit-тести для алгоритму розрахунку розміру та підрахунку суми замовлення)[cite: 6].
  * Функціональне та інтеграційне тестування за сценаріями *Given-When-Then* із матриці трасування[cite: 6].
  * Нефункціональне тестування продуктивності (Google Lighthouse) та адаптивності (360–1920 px)[cite: 6].
* **Критерії приймання:**
  * Реалізовано 100% вимог категорії **Must have (MVP)** за класифікацією MoSCoW[cite: 6].
  * Відсутні критичні та блокуючі дефекти (Severity: Blocker / Critical), через які неможливо знайти товар, підібрати розмір чи оформити замовлення[cite: 6].
  * Уся проєктна документація актуальна, пройшла рецензування та зафіксована в репозиторії[cite: 6].
* **Порядок передавання:** Виконавець публікує вихідний код і документацію у репозиторії `project-karpyshyn`, надає доступ замовнику (викладачеві) та демонструє роботу основних користувацьких сценаріїв під час захисту[cite: 6].

## 8. Умови експлуатації та супроводу
* **Гарантійні зобов'язання:** Виконавець забезпечує безкоштовне усунення виявлених помилок у логіці роботи MVP протягом **30 календарних днів** після приймання системи[cite: 6].
* **Технічна підтримка:** Звернення щодо збоїв у роботі системи фіксуються через розділ *GitHub Issues* у репозиторії проєкту. Критичні помилки (недоступність сайту, неможливість оформити замовлення) усуваються протягом **24 годин**, некритичні — протягом **3 робочих днів**[cite: 6].
* **Навчання користувачів:** Для покупців передбачено інтуїтивний інтерфейс із підказками в калькуляторі розмірів; для менеджерів та адміністратора надається текстова інструкція з прикладами додавання товарів, заповнення таблиць лекал та обробки замовлень[cite: 6].
