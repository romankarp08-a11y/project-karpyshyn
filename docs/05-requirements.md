# Специфікація вимог до програмної системи «TrendWave»

## 1. Функціональні вимоги (FR)

| ID | Назва вимоги | Опис вимоги (Система повинна...) | Роль користувача |
| :--- | :--- | :--- | :--- |
| **FR-01** | Реєстрація та автентифікація | Надавати користувачу можливість створити обліковий запис за допомогою email та пароля, а також виконувати вхід і вихід із системи. | Покупець, Менеджер, Адміністратор |
| **FR-02** | Перегляд каталогу товарів | Відображати список доступних позицій одягу з фотографією, назвою, ціною та статусом наявності з пагінацією по 20 товарів на сторінку. | Гість, Покупець |
| **FR-03** | Фільтрація та пошук | Забезпечувати пошук товарів за назвою/артикулом та фільтрацію за категорією, розміром, кольором, сезоном і діапазоном цін. | Гість, Покупець |
| **FR-04** | Перегляд картки товару | Відображати детальну сторінку товару з галереєю фото, описом складу тканини, типом крою (oversize, slim fit тощо), вибором кольору, розміру та відгуками. | Гість, Покупець |
| **FR-05** | Збереження параметрів фігури | Надавати зареєстрованому покупцю можливість зберігати та редагувати у профілі власні антропометричні заміри (зріст, обхват грудей, талії, стегон). | Покупець |
| **FR-06** | Інтелектуальний підбір розміру | Автоматично розраховувати та рекомендувати оптимальний розмір конкретної моделі одягу на основі збережених або введених користувачем замірів та таблиці лекал товару. | Гість, Покупець |
| **FR-07** | Керування списком обраного | Дозволяти авторизованому покупцю додавати товари до списку «Обране» та видаляти їх звідти. | Покупець |
| **FR-08** | Керування кошиком | Надавати користувачу можливість додавати обраний розмір і колір товару до кошика, змінювати кількість одиниць, видаляти позиції та бачити загальну суму замовлення. | Гість, Покупець |
| **FR-09** | Оформлення замовлення | Забезпечувати оформлення замовлення із заповненням контактних даних, вибором способу доставки (Нова Пошта, Укрпошта, кур'єр) та способу оплати (онлайн-оплата карткою або післяплата). | Гість, Покупець |
| **FR-10** | Відстеження статусу замовлення | Надавати покупцю можливість переглядати історію своїх замовлень та їхній поточний статус («Нове», «Підтверджено», «Відправлено», «Доставлено», «Скасовано») в особистому кабінеті. | Покупець |
| **FR-11** | Додавання відгуків про товар | Дозволяти покупцю, який придбав товар (статус замовлення «Доставлено»), залишати текстовий відгук, оцінку від 1 до 5 зірок та позначку відповідності розміру («Маломірить», «Відповідає», «Великомірить»). | Покупець |
| **FR-12** | Керування каталогом товарів | Надавати менеджеру можливість додавати нові моделі одягу, редагувати їхні описи, ціни, завантажувати фото та архівувати неактуальні позиції. | Менеджер |
| **FR-13** | Облік залишків за розмірами | Дозволяти менеджеру встановлювати й оновлювати кількість одиниць товару на складі окремо для кожної комбінації «колір + розмір» із автоматичним блокуванням замовлення при нульовому залишку. | Менеджер |
| **FR-14** | Обробка замовлень | Надавати менеджеру інтерфейс для перегляду списку замовлень, зміни їхніх статусів та додавання номера товарно-транспортної накладної (ТТН). | Менеджер |
| **FR-15** | Адміністрування користувачів і ролей | Забезпечувати адміністратору можливість призначати й змінювати ролі користувачів («Покупець», «Менеджер», «Адміністратор») та блокувати облікові записи при порушенні правил. | Адміністратор |

## 2. Нефункціональні вимоги (NFR)

| ID | Категорія | Формулювання вимоги з числовим показником | Спосіб перевірки |
| :--- | :--- | :--- | :--- |
| **NFR-01** | Продуктивність | Час завантаження сторінки каталогу (20 товарів) або картки товару не повинен перевищувати **1,5 секунди** за стандартного 4G/Wi-Fi з'єднання (швидкість від 10 Мбіт/с). | Навантажувальне та продуктивне тестування за допомогою Google Lighthouse або Chrome DevTools (вкладка Network). |
| **NFR-02** | Продуктивність (Масштабованість) | Система повинна стабільно обробляти до **200 одночасних активних користувачів** без деградації часу відповіді API понад **500 мс** для 95% запитів (95-й перцентиль). | Навантажувальне тестування за допомогою Apache JMeter або k6 (імітація 200 віртуальних користувачів). |
| **NFR-03** | Безпека | Усі паролі користувачів повинні зберігатися в базі даних виключно у вигляді криптографічного хешу з використанням алгоритму **bcrypt** (фактор вартості не нижче **10**) або **Argon2id**. | Інспекція вихідного коду модуля автентифікації та перевірка структури таблиці користувачів у БД. |
| **NFR-04** | Безпека | Весь мережевий трафік між клієнтом і сервером повинен передаватися виключно за захищеним протоколом **HTTPS (TLS 1.2 або 1.3)** із автоматичним перенаправленням усіх HTTP-запитів (код **301**). | Перевірка SSL-сертифіката через сервіс SSL Labs та тестування HTTP-запитів через cURL / браузер. |
| **NFR-05** | Зручність (Usability) | Новий користувач повинен мати змогу знайти потрібний товар, обрати розмір і оформити замовлення не більше ніж за **4 кроки** та витратити на це не більше **3 хвилин** без попереднього навчання. | Юзабіліті-тестування на фокус-групі з 5 користувачів із заміром часу та кількості кліків. |
| **NFR-06** | Сумісність | Вебінтерфейс повинен коректно відображатися (без горизонтальної прокрутки та накладання елементів) на екранах шириною від **360 px** (смартфони) до **1920 px** (десктопи) в останніх двох версіях браузерів Chrome, Firefox, Safari та Edge. | Кросбраузерне та адаптивне тестування у Chrome DevTools (Device Mode) і сервісі BrowserStack. |
| **NFR-07** | Надійність | Доступність системи (Uptime) повинна становити не менше **99,5%** на місяць (допустимий час простою — не більше **3,6 години** на місяць), а резервне копіювання БД повинно виконуватися автоматично кожні **24 години**. | Аналіз логів моніторингу доступності (наприклад, UptimeRobot) та перевірка розкладу cron-завдань резервного копіювання. |
| **NFR-08** | Супровідність | Покриття критичної бізнес-логіки (розрахунок рекомендованого розміру, підрахунок суми кошика, списання залишків) автоматизованими unit-тестами повинно становити не менше **75%**. | Запуск звіту покриття коду тестами (наприклад, за допомогою `pytest-cov` або `Jest`). |
